# Бэкап docker-проектов в S3

Один скрипт на сервер, по файлу настроек на проект. Каждую ночь снимает дамп
Postgres и зеркалит медиа в S3, старое чистит само. Ставить на сервер ничего не
нужно, кроме docker: дамп делает `pg_dump` из контейнера базы (версия всегда
совпадает), а в S3 льёт rclone в контейнере.

## Что лежит в бакете

```
<бакет>/<S3_PREFIX>/<проект>/
  db/daily/catalog_2026-11-03_033000.dump     последние 7
  db/weekly/...                               последние 4, раз в неделю
  db/monthly/...                              последние 6, раз в месяц
  media/catalog/current/...                   зеркало папки как есть
  media/catalog/deleted/2026-11-03_033000/... удалённое и перезаписанное, 30 дней
```

- **База.** Перед заливкой дамп целиком прочитывается `pg_restore`, так что
  битый дамп не вытеснит хорошие. Недельная копия появляется, когда последней
  недельной исполнилось 7 дней, месячная — когда в этом месяце её ещё нет: первый
  же прогон сразу кладёт по копии во все три папки, а пропущенный день не
  оставляет дыры. Сроки в `s3.env`, у проекта можно свои.
- **Медиа.** Заливаются только новые и изменённые файлы. Файл, который удалили
  или перезаписали на диске, не пропадает из бэкапа, а переезжает в `deleted/` с
  датой прогона и живёт там `MEDIA_KEEP_DELETED_DAYS` дней. Если папка-источник
  пустая или тома нет, синхронизация не запускается: это почти всегда опечатка в
  пути, и иначе она «удалила» бы всё зеркало.

## Установка на сервер

Всё, кроме ключей, уже в репозитории: `s3.env` (Selectel, бакет, сроки) и
`projects/audiveris.env`. Ключ — S3-ключ сервисного пользователя Selectel с
доступом к бакету.

В папке репозитория на сервере, от root:

```bash
git pull
```
```bash
cp ops/backup/secrets.env.example ops/backup/secrets.env && nano ops/backup/secrets.env
```
```bash
ops/backup/backup.sh install
```

`install` проверяет запись в бакет, контейнер базы и том с медиа и, если всё в
порядке, ставит запуск каждую ночь в 3:30 (`/etc/cron.d/docker-backup`, лог —
`/var/log/docker-backup.log`). Если что-то не так, пишет что и в cron не
ставит. Первый бэкап можно не ждать: `ops/backup/backup.sh run`.

Ещё один проект на этом же сервере — ещё один файл `projects/<имя>.env`, имя
файла — папка в бакете. Проект на другом сервере — скопируйте туда папку
(`scp -r ops/backup root@server:/opt/backup`), уберите `projects/audiveris.env`,
положите свой проект и `secrets.env`, затем `install`. Бакет тот же; чтобы
серверы не путались, им можно задать разные `S3_PREFIX`.

## Уведомления

Токены и адреса — в `secrets.env`.

- `TG_BOT_TOKEN` + `TG_CHAT_ID` — при любой ошибке в Telegram приходит
  сообщение с логом упавших проектов. Проект, который упал, не мешает остальным.
- `HEALTHCHECK_URL` (например, healthchecks.io) — ловит то, что Telegram не
  поймает: бэкап вообще не запустился (cron сломался, сервер лежал, диск
  кончился).

## Восстановление

```bash
ops/backup/backup.sh list audiveris
```

База — последний дамп или конкретный, можно в другую базу рядом, чтобы
сначала посмотреть:

```bash
ops/backup/backup.sh restore-db audiveris latest --db catalog_check
```
```bash
ops/backup/backup.sh restore-db audiveris weekly/catalog_2026-10-27_033000.dump
```

Восстановление поверх рабочей базы перезаписывает её; перед этим остановите
приложение (`docker compose stop audiveris-api`), иначе его соединения могут
держать блокировки. Скрипт спросит подтверждение (`--yes` — без вопроса).

Медиа — в том или папку (копирует, лишнего не удаляет), или отдельно файлы из
архива удалённого:

```bash
ops/backup/backup.sh restore-media audiveris catalog audiveris-api_storage:/out/catalog
```
```bash
ops/backup/backup.sh restore-media audiveris catalog /tmp/old --from deleted/2026-11-03_033000
```

Файлы восстанавливаются от root — если приложение работает от другого
пользователя, сделайте `chown`.

## Важно знать

- Ключ на сервере умеет удалять, значит, взломанный сервер может стереть и
  бэкапы. Если это критично, включите в бакете версионирование с правилом
  удалять старые версии через N дней.
- Дампы не шифруются: защищены только доступом к бакету.
- Только Postgres из официального образа (или совместимого: вход через
  локальный сокет без пароля). Иначе задайте `DB_USER`/`DB_PASSWORD`.
